# خطة بناء Islamic Life OS — مقسّمة إلى مراحل وحزم عمل صغيرة

> **الحالة:** مسودة للاعتماد (بتاريخ 2026-10-14).
> **المرجع:** فكرة التطبيق في ملفات الحزمة، ونتائج التدقيق في `audit/`.
> **مبدأ الخطة:** لا ننتقل إلى حزمة عمل قبل أن تجتاز الحزمة السابقة بوابة الجودة الخاصة بها. كل حزمة صغيرة يمكن مراجعتها واختبارها والرجوع عنها.

---

## 0. كيف تُستخدم هذه الخطة

- الخطة مقسّمة إلى **مراحل**، وكل مرحلة مقسّمة إلى **حزم عمل** (مثل 1.4 أو 2.10).
- حجم كل حزمة يتراوح بين يوم وخمسة أيام عمل.
- كل حزمة تتضمن: الهدف، وما تعتمد عليه، والمخرجات، والاختبارات، ومعيار القبول.
- كل حزمة تُنفّذ في فرع git مستقل وطلب دمج (Pull Request) صغير، ولا تُدمج إلا بعد نجاح CI والمراجعة.
- في نهاية كل مرحلة توجد **بوابة خروج**، ولا تبدأ المرحلة التالية قبل اجتيازها.
- أي تغيير في القرارات المذكورة في القسم 1 يُسجَّل في سجل القرارات المعمارية (ADR) قبل التنفيذ.

## 2. استراتيجية دعم جميع اللغات

### 2.1 المبدأ

«يدعم جميع اللغات» له معنيان، ويُنفّذان بطريقتين مختلفتين:

1. **البنية تدعم أي لغة من اليوم الأول.** أي لغة جديدة تُضاف بإضافة ملفات ترجمة فقط، دون أي تعديل في الكود. هذا الجزء إلزامي من المرحلة 1.
2. **الترجمة الفعلية تُضاف على موجات.** ترجمة الواجهة ممكنة لأي لغة. أما **المحتوى الديني** (ترجمات معاني القرآن، والتفسير، والحديث) فيُضاف فقط عندما يتوفر له مصدر موثوق ومرخّص بتلك اللغة.

**لا تُستخدم الترجمة الآلية لنص ديني أبدًا.** يمكن استخدامها لمسودات نصوص الواجهة فقط، بشرط مراجعة بشرية من متحدث أصلي قبل النشر.

### 2.2 المتطلبات التقنية (تُبنى في المرحلة 1)

| البند | التنفيذ |
|---|---|
| النصوص | لا يوجد أي نص مكتوب مباشرة في الكود. قاعدة Lint `HardcodedText` تُعامَل كخطأ يوقف البناء. |
| تغيير اللغة داخل التطبيق | دعم اختيار لغة خاصة بالتطبيق (Per-app language)، مع `locales_config.xml` لأندرويد 13 فما فوق، و`AppCompatDelegate.setApplicationLocales` للإصدارات الأقدم. |
| الجمع | استخدام `plurals` ورسائل ICU دائمًا. العربية لها 6 صيغ جمع، ولا يُسمح بتركيب الجمل يدويًا. |
| الاتجاه | RTL وLTR معًا. تُستخدم `start/end` بدل `left/right` في كل مكان، وتُعكس الأيقونات الاتجاهية (الأسهم) تلقائيًا. |
| الأرقام والتواريخ | التنسيق حسب الـ Locale (مثل ٠١٢ أو 012، و12 أو 24 ساعة)، مع إعداد يدوي للأرقام. التاريخ الهجري يُعرض بلغة المستخدم. |
| الخطوط | عائلة Noto لتغطية جميع أنظمة الكتابة (عربي، أردو/نستعليق، بنغالي، ديفاناغاري، صيني...)، وخط قرآني مرخّص مستقل لنص المصحف فقط. |
| أطوال النصوص | التصميم يتحمل النصوص الطويلة (الألمانية والروسية أطول من العربية بنحو 30–40%)، ويتحمل تكبير الخط إلى 200%. |
| اختبار مبكر دون ترجمة | تفعيل اللغات الوهمية (Pseudo-locales) `en-XA` و`ar-XB` في نسخة التطوير، لكشف النصوص غير المترجمة ومشاكل الاتجاه. |
| منصة الترجمة | Weblate ذاتي الاستضافة (أو منصة مماثلة) متصل بالمستودع، وتظهر فيه نسبة الإنجاز لكل لغة. |
| الخادم | يستخدم ترويسة `Accept-Language` مع سلسلة بدائل (اللغة المطلوبة ← الإنجليزية ← العربية). رسائل الأخطاء تُرجَع كأكواد ثابتة، ويترجمها التطبيق. |
| قاعدة البيانات | كل محتوى قابل للترجمة له جدول ترجمات `(item_id, language, text, source_id, status)`، ولا تُضاف أعمدة مثل `title_ar` و`title_en`. |
| البحث | تطبيع النص خاص بكل لغة: للعربية حذف التشكيل وتوحيد الهمزات والتاء المربوطة، ولغيرها التطبيع المناسب لها. |
| اللغة الافتراضية | لغة الجهاز إذا كانت مدعومة، وإلا الإنجليزية. يمكن اختيار العربية من شاشة الترحيب. |

### 2.3 موجات اللغات (مقترحة، ويمكن تعديلها)

| الموجة | اللغات | التوقيت |
|---|---|---|
| 1 | العربية، والإنجليزية | مع الإطلاق الأول |
| 2 | الأردية، والإندونيسية، والتركية، والفرنسية، والبنغالية، والملايوية، والفارسية | بعد الإطلاق التجريبي |
| 3 | الروسية، والإسبانية، والألمانية، والهوسا، والسواحلية، والصومالية، والبشتو، والأوزبكية، والصينية، وغيرها | تدريجيًا حسب الطلب وتوفر المحتوى |

**معيار قبول أي لغة جديدة:**

1. نصوص الواجهة مترجمة 100% وراجعها متحدث أصلي.
2. قواعد الجمع والأرقام والتواريخ مختبرة.
3. الخط يغطي جميع حروف اللغة.
4. لقطات الشاشة الآلية لجميع الشاشات الأساسية ناجحة.
5. ترجمة معاني القرآن (إن وُجدت) مرخصة ومنسوبة لمصدرها.
6. وصف المتجر مترجم.

## 3. قواعد منع الأخطاء البرمجية (تُطبّق على كل حزمة عمل)

### 3.1 خط CI الإلزامي (لا يُدمج أي كود إذا فشل)

1. بناء Android بنسختي Debug وRelease.
2. Android Lint وdetekt وktlint، بلا أخطاء جديدة.
3. اختبارات الوحدة للتطبيق والخادم.
4. اختبارات لقطات الشاشة (Roborazzi أو Paparazzi) بالعربية والإنجليزية، وبالوضعين الفاتح والداكن، وبتكبير الخط.
5. اختبارات ترحيل Room (Migration tests).
6. تطبيق ترحيلات PostgreSQL على قاعدة فارغة داخل حاوية (Testcontainers).
7. **فحص عقد OpenAPI:** أي تغيير يكسر التوافق يُرفض تلقائيًا ما لم يُرفع رقم الإصدار.
8. فحص الأسرار (Secret scan) وفحص الثغرات في التبعيات.
9. فحص النصوص غير المترجمة، والنصوص المكتوبة مباشرة في الكود.

### 3.2 قواعد الكود

- **طبقات واضحة:** واجهة (UI) ← ViewModel ← حالات استخدام (Use cases) ← مستودعات (Repositories) ← مصادر بيانات. وحدات الميزات لا تعتمد على بعضها مباشرة.
- **منطق الأعمال** (حساب المواقيت، والقبلة، والهجري، والمزامنة، وتطبيع البحث) يكون في كود Kotlin نقي قابل للاختبار، دون اعتماد على أندرويد. نسبة تغطيته بالاختبارات 80% أو أكثر.
- **الأخطاء:** نوع موحد للنتائج والأخطاء. لا يُستخدم `!!` ولا تُبتلع الاستثناءات. كل خطأ يظهر في الواجهة كحالة واضحة.
- **أعلام الميزات (Feature flags):** أي ميزة غير مكتملة مخفية في نسخة الإنتاج، فلا تظهر أزرار وهمية.
- **التنقل** آمن الأنواع (Type-safe navigation).
- **أدوات التطوير:** StrictMode وLeakCanary في نسخة التطوير.
- **السجلات:** طبقة إخفاء البيانات الحساسة إلزامية. لا يُسجَّل محتوى المستخدم ولا روابط التصفح.
- **حجم طلب الدمج:** صغير قدر الإمكان (يُفضّل أقل من 400 سطر)، مع وصف ونتائج الاختبارات.

### 3.3 تعريف «مكتمل» (Definition of Done) لكل حزمة

- [ ] الكود مدمج وCI ناجح.
- [ ] الاختبارات المذكورة في الحزمة مكتوبة وناجحة.
- [ ] حالات التحميل والفراغ والخطأ وانقطاع الاتصال ورفض الصلاحية منفذة (إن كانت تنطبق).
- [ ] النصوص في ملفات الترجمة، وتعمل بالعربية والإنجليزية في الاتجاهين RTL وLTR.
- [ ] تعمل مع قارئ الشاشة TalkBack وتكبير الخط.
- [ ] التوثيق محدث، بما فيه أي ADR جديد.
- [ ] تقرير قصير: ما تم، والملفات، والأوامر، والنتائج الفعلية.

  core/i18n                    ← اللغة، تنسيق الأرقام والتواريخ، تطبيع البحث

  core/security                ← Keystore، التشفير، قفل التطبيق
  core/notifications           ← قنوات الإشعارات
  platform/alarm               ← المنبهات الدقيقة، إعادة الجدولة، الإقلاع
  feature/onboarding
  feature/auth
  feature/home
  feature/prayer               ← المواقيت + القبلة + الهجري
  feature/quran                ← القارئ + التفسير + الترجمات (والحفظ لاحقًا)
  feature/settings
  (تُضاف لاحقًا: adhkar, library, protection + platform/vpn, recovery, alarm, focus, assistant)

backend/
  src/Api                      ← نقطة الدخول، OpenAPI، الترجمة، الأخطاء
  src/Modules/Identity
  src/Modules/UserData         ← الإعدادات والمزامنة
  src/Modules/Content          ← المحتوى، المصادر، التراخيص، الإصدارات، الترجمات
  src/Modules/Cms              ← (المرحلة 3)
  src/Worker                   ← المهام الخلفية
  tests/
tools/content-pipeline/        ← استيراد المحتوى والتحقق منه وتوقيع الحزم
infra/                         ← Docker Compose، الوكيل العكسي، النسخ الاحتياطي
docs/adr/                      ← سجل القرارات
api/openapi.yaml               ← العقد
