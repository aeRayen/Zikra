# مخطط بيانات الخادم V1 — الحزمة 0b.4

**الملف التنفيذي المقترح:** [V1__init.sql](V1__init.sql).

**الحالة:** مُصمَّم ولم يُنفَّذ بعد. يصبح معتمدًا فقط بعد نجاحه على قاعدة فارغة في CI (الحزمة 1.10).

## 1. التقسيم

| Schema | المحتوى | من يكتب فيه |
|---|---|---|
| `identity` | المستخدمون، والجلسات، والـ nonces | وحدة Identity فقط |
| `userdata` | الموافقات، والإعدادات، والعلامات، وموضع القراءة، وأهداف العبادة وتقدمها | وحدة UserData فقط |
| `content` | اللغات، والمصادر، والقرآن، والترجمات، والتفسير، والأذكار، والإصدارات | أداة المحتوى ولوحة الإدارة. واجهة API تقرأ فقط |
| `ops` | مفاتيح عدم التكرار، وطلبات الحذف، والتصدير، وسجل التدقيق | الخادم والعامل الخلفي |
| `cms` | المحررون، والأدوار، ونسخ المحتوى | **V2**، في المرحلة 3 |

## 2. ما الذي عالجه V1 من التدقيق (`audit/ARCHITECTURE_REVIEW.md` §7)

| الخلل | المعالجة |
|---|---|
| D1 الحذف الناعم مع `google_subject` | حذف فعلي بعد مهلة، والحالة المعلقة في `ops.deletion_requests` |
| D2 `updated_at` بلا تحديث | Triggers: `bump_version` و`touch_updated_at` |
| D3 قيم نصية حرة | قيود CHECK |
| D4/C7 الموقع الدقيق | `lat_rounded` و`lon_rounded` بدقة 0.1°، أو `city_id` |
| D5 JSONB غير مُتحقق | أُزيل، وصارت أعمدة محددة |
| D6 تفرّد التقدم مع NULL | `goal_id NOT NULL` وفهرس تفرّد جزئي |
| D7 أهداف ناقصة | أُضيف `title` و`period` و`archived` و`updated_at` |
| D8/D9 القرآن بنسخة واحدة | `quran_editions` و`quran_ayah_meta` و`quran_ayah_texts`، و`search_text` منفصل، و`source_id NOT NULL` |
| D11 تفسير لآية واحدة | `ayah_from` و`ayah_to` |
| D12 الترخيص نص حر | `license_code` و`allows_offline` و`allows_modification` و`verified_*` |
| D13/D14 بيانات التعافي | أُزيلت من الخادم (ADR-011) |
| D15/D16 المنبه | محلي فقط في الإصدار الأول |
| D17 `protection_profiles` | أُزيل (ADR-011) |
| D19 الإصدارات | توقيع، ومفتاح، وحالة، ولغة، ونسخة |
| D20 التدقيق | `actor_role` و`details` |
| D21 الفهارس | فهارس المزامنة `(user_id, server_version)` والبحث |
| D22 pgcrypto | أُزيل، فـ `gen_random_uuid()` مدمج في PostgreSQL |
| D23 سكربت مسطح | صار ترحيلًا مرقّمًا `V1__` |
| C10 الجلسات | `identity.auth_sessions` مع عائلة تدوير |
| تعدد اللغات | `content.languages` وجداول أسماء وترجمات لكل لغة |

## 4. أدوار قاعدة البيانات (تُنشأ بسكربتات البنية التحتية)

| الدور | الصلاحيات |
|---|---|
| `app_migrator` | DDL على جميع الـ schemas، ويُستخدم في النشر فقط |
| `app_api` | SELECT وINSERT وUPDATE وDELETE على `identity` و`userdata` و`ops`، وSELECT فقط على `content` |
| `app_content` | كتابة على `content` فقط، لأداة المحتوى ولوحة الإدارة |
| `app_backup` | قراءة للنسخ الاحتياطي |

**لا يملك أي دور تشغيل صلاحية superuser.**

## 5. الحذف والاحتفاظ

| البيان | المدة / الآلية |
|---|---|
| مهلة التراجع عن الحذف | 14 يومًا (مقترح) |
| حذف المستخدم | `DELETE FROM identity.users` يحذف كل شيء في `userdata` والجلسات بـ CASCADE |
| `ops.audit_events` | يبقى السجل، ويصير `actor_user_id = NULL` |
| النسخ الاحتياطية | تتقادم خلال 35 يومًا (مقترح، يُذكر في سياسة الخصوصية) |
| السجلات المحذوفة (tombstones) | 90 يومًا. بعدها يرجع `/sync/pull` الرمز 410 للمؤشرات القديمة |
| مفاتيح عدم التكرار | 48 ساعة |
| ملفات التصدير | 7 أيام |
