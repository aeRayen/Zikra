# معمارية Supabase لتطبيق «ذِكْرَى» (Zikra)

**المرجع:** ADR-024 وADR-025.

**الهدف:** تطبيق يعمل على الجهاز أولًا، مع حسابات اختيارية تبقى آمنة ومنخفضة التكلفة حتى مع ملايين المستخدمين حول العالم.

---

## 1. الصورة الكاملة

```
┌──────────────── هاتف المستخدم (المصدر الأول للبيانات) ────────────────┐
│ content.db (قرآن/ترجمات/أذكار)  user.db (علامات/أهداف)  private.db 🔒   │
│            ▲                         ▲   (اختياري)                      │
└────────────┼─────────────────────────┼─────────────────────────────────┘
             │ HTTPS (ملفات ثابتة)      │ HTTPS (فقط لمن سجّل دخوله)
┌────────────┴───────────┐   ┌────────┴────────────────────────────────┐
│ CDN + تخزين ملفات      │   │ Supabase                                  │
│ (مثل Cloudflare R2)    │   │  Auth: Google / بريد إلكتروني            │
│ حزم موقّعة              │   │  Postgres: app.* + RLS ، api.* (RPC)     │
│ بلا رسوم نقل بيانات     │   │  Edge Functions: حذف الحساب، التصدير     │
└────────────────────────┘   └───────────────────────────────────────────┘
        بيانات التعافي والحماية لا تغادر الهاتف أبدًا (ADR-011)
```

## 2. ما يُخزَّن وأين

| البيانات | الجهاز | Supabase | CDN |
|---|---|---|---|
| القرآن، والترجمات، والتفسير، والأذكار | ✔ | ✘ | ✔ (المصدر) |
| الإعدادات، والعلامات، وموضع القراءة، والأهداف | ✔ (الأساس) | ✔ نسخة اختيارية بموافقة لكل فئة | ✘ |
| الحساب (المعرّف، والبريد، والاسم) | جلسة فقط | ✔ (Supabase Auth) | ✘ |
| ملاحظات العلامات | ✔ | ✘ (ADR-012) | ✘ |
| الموقع الدقيق | ✔ | ✘. المدينة أو موقع مقرّب إلى 0.1° فقط | ✘ |
| التعافي، والحماية، والمنبه | ✔ (مشفّر) | ✘ | ✘ |

**المستخدم الضيف لا يتصل بـ Supabase نهائيًا.** يُنشأ له حساب فقط عندما يختار تسجيل الدخول.

## 3. طرق تسجيل الدخول

| الطريقة | ماذا تحتاج | التكلفة | التوصية |
|---|---|---|---|
| **Google** | مشروع Google Cloud لمفاتيح OAuth | **مجاني** | ✔ الأساسية. يستخدم Credential Manager مع `signInWithIdToken` |
| **رمز عبر البريد الإلكتروني (OTP)** | خدمة إرسال بريد (SMTP)، لأن بريد Supabase المدمج للتجربة فقط وبحدود منخفضة | باقات مجانية محدودة، ثم مدفوعة | ✔ بديل لمن لا يريد Google |
| Apple | حساب Apple Developer (مدفوع) | سنوي | عند إطلاق iOS |
| رسائل SMS | مزوّد رسائل | **مكلف لكل رسالة** | ✘ لا ننصح به |
| تسجيل مجهول تلقائي | — | يُحتسب مستخدمًا نشطًا | ✘ (ADR-025 §2) |

## 4. الأمان (إلزامي)

1. **RLS مفعّل على كل جدول**، والسياسة `user_id = auth.uid()`.
2. **التطبيق يحمل المفتاح العام فقط.** مفتاح `service_role` لا يوجد إلا في Edge Functions وأسرار CI.
3. **الجداول في مخطط `app` غير مكشوفة.** التطبيق يستدعي دوال `api.*_v1` فقط، وهي تتحقق من المدخلات وتطبق قواعد المزامنة.
4. **`user_id` يُفرض بـ Trigger** من الرمز، وما يرسله التطبيق يُتجاهل.
5. **اختبارات pgTAP في CI** تثبت أن مستخدمًا لا يستطيع قراءة بيانات غيره أو تعديلها.
6. **تحديد معدل الطلبات** (حدود Supabase Auth، مع حدود داخل الدوال)، وحجم أقصى للطلب.
7. **حذف الحساب** يمر بـ Edge Function تستخدم `auth.admin.deleteUser`، بعد مهلة 14 يومًا. الحذف يمسح كل بيانات المستخدم بـ CASCADE.
8. **المنطقة الجغرافية** لمشروع Supabase تُختار حسب دول الإطلاق والقوانين (ADR-P04). مثلًا أوروبا إن كان المستخدمون في الاتحاد الأوروبي.

## 5. العمل لملايين المستخدمين

| المبدأ | التطبيق |
|---|---|
| الخادم ليس في المسار اليومي | المواقيت والقرآن والأذكار والمنبه تعمل دون أي اتصال |
| لا ذروة متزامنة | المزامنة تتأخر وقتًا عشوائيًا (0–30 دقيقة)، ولا تُربط بوقت الأذان أبدًا |
| دفعات صغيرة | 200 تغيير كحد أقصى لكل استدعاء، والسحب بالمؤشر |
| فهارس المزامنة | `(user_id, server_version)` على كل جدول |
| المحتوى من CDN | ملف الترجمة يُنزَّل مرة لكل جهاز، ويُخزَّن مؤقتًا في CDN |
| اتصالات قاعدة البيانات | الدوال تمر عبر مجمّع الاتصالات (Supavisor) المدمج في Supabase |
| الإصدارات | `api.*_v1` تبقى عاملة عند إضافة `_v2`، حتى لا تتعطل الإصدارات القديمة من التطبيق |

## 6. التكلفة التقديرية

**الأسعار تقريبية وقت كتابة هذه الوثيقة، ويجب التحقق منها على صفحة أسعار Supabase قبل الاعتماد.**

| الباقة | ما تشمله تقريبًا | مناسبة لـ |
|---|---|---|
| مجانية | نحو 50 ألف مستخدم نشط شهريًا، وقاعدة بيانات صغيرة. **المشروع يتوقف بعد فترة خمول** | التطوير والاختبار فقط |
| Pro | نحو 25 دولارًا شهريًا، وتشمل نحو 100 ألف مستخدم نشط، ثم سعر صغير لكل مستخدم إضافي (نحو 0.003 دولار) | الإطلاق |

**النقطة المهمة:** التكلفة تُحسب على **المستخدمين المسجّلين الذين يتصلون خلال الشهر**، وليس على عدد التثبيتات.

| السيناريو | المسجّلون النشطون شهريًا | تكلفة Auth التقريبية شهريًا |
|---|---|---|
| مليون تثبيت، 10% منهم يسجّلون الدخول | 100 ألف | نحو 25 دولارًا (ضمن Pro) |
| 5 ملايين تثبيت، 10% يسجّلون | 500 ألف | نحو 25 دولارًا + 400 ألف × 0.003 ≈ **1,300 دولار** |
| 5 ملايين تثبيت، 50% يسجّلون | 2.5 مليون | ≈ **7,800 دولار** |

يُضاف إلى ذلك حجم قاعدة البيانات والخادم الأكبر عند الحاجة، وتكلفة CDN (منخفضة مع R2).

**لهذا السبب تحديدًا** جعلنا التطبيق يعمل كاملًا دون حساب. وعند الوصول إلى ملايين المستخدمين يمكن نقل Supabase إلى **استضافة ذاتية** (مفتوح المصدر) أو خادم خاص، دون تغيير كود التطبيق، لأن الوصول يمر عبر واجهات Repository.

**مراقبة التكلفة:** حدّ إنفاق (Spend cap) وتنبيهات في لوحة Supabase من اليوم الأول.

## 7. بيئات العمل

| البيئة | الأداة |
|---|---|
| تطوير محلي | Supabase CLI (`supabase start`) يشغّل Supabase كاملًا على الجهاز عبر Docker، **مجانًا وبلا حساب** |
| اختبار (staging) | مشروع Supabase مجاني |
| إنتاج | مشروع Supabase Pro، عند الإطلاق |
| الترحيلات | ملفات `supabase/migrations/*.sql` في git، تُطبَّق عبر CI. لا تعديل يدوي على قاعدة الإنتاج |

## 8. التطبيق (Android)

- **الواجهات أولًا:** واجهات `AuthRepository` و`SyncRepository` في `core`، ولها تنفيذ Supabase منفصل في وحدة `data:supabase`. يمكن استبداله لاحقًا دون تغيير الميزات.
- **مكتبة Kotlin لـ Supabase:** مجتمعية ومذكورة في توثيق Supabase، أو استدعاء REST مباشر بـ OkHttp. **يُحسم الخيار في الحزمة 1.8 بعد فحص نضج المكتبة وحجمها.**
- **الجلسة:** تُخزَّن مشفّرة بمفتاح من Keystore. التجديد تلقائي.

## 9. ما تغيّر في الوثائق السابقة

| الوثيقة | التغيير |
|---|---|
| `api/openapi.yaml` | مسارات `/auth/*` و`/me/*` و`/sync/*` صارت دوال `api.*_v1` وSupabase Auth. مسارات `/content/*` صارت ملفات ثابتة على CDN. يبقى الملف مرجعًا لأشكال البيانات (Schemas) |
| `data/V1__init.sql` | أجزاء `identity` و`userdata` و`ops` حل محلها `data/supabase/V1__init.sql`. جزء `content` باقٍ لأداة المحتوى |
| `SYNC_PROTOCOL_AR.md` | **المنطق نفسه** (التعارضات، والمؤشر، والدفعات)، والنقل عبر RPC بدل REST |
| `plan/BUILD_PLAN_AR.md` | حزم المرحلة 1 الخاصة بالخادم تغيّرت (انظر التحديث في الخطة) |
