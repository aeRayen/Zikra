# مواصفة حزم المحتوى — الحزمة 0b.7

**المرجع:** ADR-014.

**الهدف:** وصول المحتوى الديني إلى الجهاز **كما هو تمامًا** من مصدره المرخّص، مع القدرة على كشف أي تعديل أو تلف.

## 1. ما هي الحزمة

- ملف SQLite واحد أو أكثر، مع ملف `manifest.json` يصفها.
- يُوقَّع الـ manifest بمفتاح Ed25519 خاص لا يوجد إلا في بيئة بناء المحتوى. **لا يوجد المفتاح على خادم API.**
- المفتاح العام (أو أكثر من مفتاح، للتدوير) مُضمَّن في التطبيق.

| المجال (`area`) | أمثلة | اللغة |
|---|---|---|
| `quran_text` | `ar.hafs.uthmani` | `ar` |
| `quran_translation` | ترجمة معانٍ واحدة لكل حزمة | لغة الترجمة |
| `tafsir` | تفسير واحد لكل حزمة | لغة التفسير |
| `adhkar` | النص العربي + ترجمات لغة واحدة | لغة الترجمة (والعربي مضمَّن) |
| `hadith`، `library` | المرحلة 3 | |
| `blocklist` | المرحلة 4 | بلا لغة |

## 2. صيغة الـ manifest

```json
{
  "schema": 1,
  "packId": "6f1c2a4e-0000-4000-8000-000000000000",
  "area": "quran_translation",
  "language": "id",
  "editionCode": "id.example-translation",
  "version": "2026.10.1",
  "minAppVersion": "1.0.0",
  "createdAt": "2026-10-14T00:00:00Z",
  "source": {
    "name": "<اسم المصدر>",
    "licenseCode": "LicenseRef-<...>",
    "licenseUrl": "https://…",
    "attribution": "<نص النسبة المطلوب>",
    "allowsOffline": true,
    "allowsModification": false
  },
  "files": [
    { "path": "pack.sqlite", "sizeBytes": 1234567, "sha256": "<64 hex>" }
  ],
  "verification": {
    "surahCount": 114,
    "ayahCount": 6236,
    "perSurahAyahCountsSha256": "<64 hex>"
  }
}
```

- القيم أعلاه **أمثلة للشكل فقط**، وليست مصادر حقيقية.
- يُوقَّع **نص الـ manifest بالبايتات كما هي**. يُرسل كنص Base64 مع التوقيع، فلا يحدث اختلاف بسبب إعادة تنسيق JSON.

## 3. التحقق على الجهاز (بالترتيب، ويُرفض عند أول فشل)

1. `keyId` معروف وغير مُلغى.
2. توقيع Ed25519 صحيح على بايتات الـ manifest.
3. `minAppVersion` ≤ إصدار التطبيق.
4. التنزيل إلى مجلد مؤقت، ثم مطابقة `sizeBytes` و`sha256` لكل ملف.
5. فتح الملف للقراءة فقط وفحص `PRAGMA integrity_check`.
6. فحوص المجال:
   - **القرآن والترجمات:** 114 سورة و6236 آية، وتطابق عدد آيات كل سورة مع البصمة.
   - **الأذكار:** لكل ذكر مرجع.
7. تثبيت ذري: نقل الملف، ثم تسجيله في `installed_pack`، ثم حذف الإصدار القديم.

**أي فشل** يؤدي إلى: حذف الملف المؤقت، وإبقاء الإصدار السابق، وتسجيل حدث بلا بيانات شخصية، وإعادة المحاولة لاحقًا.

## 4. أداة بناء المحتوى (`tools/content-pipeline`، الحزمة 1.15)

1. **استيراد** من ملف المصدر الأصلي، بعد تسجيل المصدر والترخيص في `content.sources` مع `verified_by`.
2. **تحقق:** الأعداد، والترتيب، وعدم وجود آيات فارغة، وأن النص مطابق بايتًا ببايت للمصدر (بصمة SHA-256 للملف الأصلي محفوظة).
3. **توليد `search_text`** بالتطبيع، في عمود منفصل.
4. **بناء** ملف SQLite بمخطط `content.db`.
5. **توقيع** الـ manifest، ويتم في بيئة معزولة.
6. **نشر:** رفع الملفات إلى التخزين الثابت، وإضافة سجل في `content.releases` بحالة `draft`، ثم `published` بعد المراجعة.

**ممنوع:** أي خطوة تعدّل النص الأصلي، كإصلاح «أخطاء إملائية» أو تغيير الترميز. إن احتاج المصدر تطبيعًا لترميز Unicode (مثل NFC)، فقرار صريح يُوثَّق ويُختبر، وبموافقة الترخيص (`allowsModification`).

## 5. إدارة المفاتيح

- مفتاح التوقيع له معرف (`keyId`) وتاريخ.
- التطبيق يحمل المفتاح الحالي والمفتاح التالي.
- التدوير: يُضاف المفتاح الجديد إلى التطبيق قبل استخدامه بإصدار واحد على الأقل.
- عند تسريب مفتاح: يُلغى في إصدار التطبيق التالي، وتُعاد الحزم بالمفتاح الجديد.

## 6. التضمين في APK

- يُضمَّن `quran_text` العربي (نحو 2–5 MB، يُقاس فعليًا) مع المعلومات البنيوية، **إذا سمح الترخيص** (`allowsOffline`).
- الترجمات والتفسير والأذكار المترجمة تُنزَّل حسب لغة المستخدم عند الإعداد الأول، مع إمكانية الاستخدام دون اتصال بعد ذلك.
