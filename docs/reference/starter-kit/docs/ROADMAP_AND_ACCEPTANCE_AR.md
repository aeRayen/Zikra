# خارطة الطريق ومعايير القبول

## المرحلة 0 — التدقيق والتخطيط
المخرجات:
- تقرير المتطلبات.
- سجل المخاطر والافتراضات.
- مخطط الوحدات والبيانات.
- عقود API أولية.
- نموذج UX أولي.
معيار القبول: اعتماد الخطة قبل تغييرات واسعة.

## المرحلة 1 — أساس المشروع
- هيكل Gradle متعدد الوحدات.
- نظام التصميم والتنقل وRTL.
- قاعدة Room وطبقة الشبكة.
- Backend وPostgreSQL وOpenAPI.
- تسجيل Google والتحقق على الخادم.
- خط بناء واختبارات وبيئات منفصلة.
معيار القبول: بناء ناجح واختبارات أساسية وتسجيل آمن.

## المرحلة 2 — العبادة
- الصلاة والقبلة والأذكار.
- إعدادات الإشعارات.
- أول نسخة من القرآن مع علامات مرجعية.
- تنزيل المحتوى المسموح به دون اتصال.
معيار القبول: اختبار الحسابات والمحتوى والتوقيت على أجهزة حقيقية.

## المرحلة 3 — المكتبة
- الحديث والتفسير والسيرة والقصص.
- البحث والفهرسة.
- إدارة المحتوى والمصادر والإصدارات.
معيار القبول: كل مادة منشورة لها بيانات مصدر ومراجعة.

## المرحلة 4 — الحماية
- تصفية أساسية وإظهار الحالة.
- اختبارات توقف الخدمة والشبكة.
- مراجعة سياسة Google Play.
- إثبات جدوى وضع الإدارة للأجهزة المناسبة.
معيار القبول: توثيق واضح للحدود وعدم ادعاء الحجب المطلق.

## المرحلة 5 — التعافي والمنبه
- خطط تعافٍ محلية.
- زر تدخل سريع.
- جدولة المنبه ومهام التحقق.
- تحليل احتمالي لاستجابة الاستيقاظ.
معيار القبول: اختبارات إعادة التشغيل والصلاحيات والطاقة والخصوصية.

## المرحلة 6 — المساعد الذكي والتركيز
- بحث استرجاعي موثق.
- جلسات تركيز وتذكيرات.
- ضوابط منع اختلاق المراجع.
معيار القبول: اختبار عينات أسئلة ومراجعة مصادر الإجابات.

## المرحلة 7 — الإطلاق
- مراجعة أمنية.
- اختبارات الأداء والبطارية.
- اختبار استعادة النسخ الاحتياطية.
- مراجعة الخصوصية والتراخيص.
- إطلاق تجريبي ومراقبة الأعطال.

## المرحلة 8 — iOS
- إعادة استخدام الخادم وعقود API.
- تطبيق SwiftUI وتكاملات Apple الأصلية.
- إعادة تقييم ميزات الحماية والمنبه وفق قيود iOS.

## تقدير زمني
تقدير أولي لنسخة واسعة: نحو 18–25 أسبوعًا بفريق مناسب، وقد يزيد حسب جودة المحتوى ومتطلبات الحماية وحجم الفريق. لا يعد هذا وعدًا بموعد نهائي.

## معايير الجودة العامة
- لا ميزة مكتملة بلا اختبار.
- لا أزرار شكلية في إصدار الإنتاج.
- حالات تحميل وفراغ وخطأ لكل شاشة مناسبة.
- لا بيانات شخصية في السجلات بلا ضرورة.
- اختبارات عدم الاتصال والمزامنة والتعارض.
- اختبارات صلاحيات بين الحسابات.
- اختبار حذف الحساب واستعادة النسخ الاحتياطية.
- توثيق أي ميزة غير ممكنة بسبب قيود النظام.
